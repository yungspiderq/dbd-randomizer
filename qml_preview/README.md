# DBD Ultimate Search Randomizer — Qt Release Candidate 1 (testing)

Windows-версия рандомизатора Dead by Daylight на **PySide6 / Qt Quick**.

## Конструктор билдов

- Четыре визуальных слота с миниатюрами, выбором по клику и удалением перков.
- Исправлен перенос из каталога в слот, перестановка занятых слотов и отмена переноса вне области слотов.
- Поиск по перку или персонажу, фильтры «Все / Общие / Уникальные / Персонажа».
- Выбор навыков только подходящей стороны, защита от дубликатов и строгая проверка пользовательских сборок.

## Beta 16 — безопасность и стабильность

- Исправлено определение текущей версии обновления.
- При неудачном вводе автоэкипировка останавливается, а неподтверждённая конфигурация не записывается как достоверная.
- Защита от повторного запуска автоматизации, новые регрессионные тесты.
- Сохранены темы Crimson / Frost / Violet, избранное, статистика, ротация, скины и аддоны.

## Установка

После публикации Beta 16 можно обновиться через «Проверить обновления» из Beta 15. При ручной установке скачайте ZIP из GitHub Releases, полностью распакуйте его и запускайте EXE вместе с папкой `_internal`.

Перед обновлением рекомендуется резервная копия `dbd_randomizer_config.json`.

Исходники (Python 3.12+):

```powershell
py -m pip install -r qml_preview/requirements.txt
py qml_preview/main.py
```

Windows CI проверяет backend, реальные взаимодействия с конструктором в Qt offscreen, portable EXE и ZIP. Автоэкипировку сначала запускайте в сухом прогоне. F9 останавливает выполнение.

## Проверки автоэкипировки (этап 3)

Перед каждым вводом проверяется фокус окна Dead by Daylight. При потере фокуса автоматизация прекращается; она не возвращает окно игры автоматически. Если включена OCR-проверка, необходимо настроить область OCR: пустое распознавание не считается успешным поиском. OCR проверяет видимый текст, **но не гарантирует, что навык действительно экипирован**. Сначала выполните сухой прогон. Стоп — назначенная клавиша (по умолчанию F9) или кнопка интерфейса.

## Qt UI performance (этап 4)

- Загрузка серии изображений вызывает не больше одного обновления каталога за короткий интервал (120 мс), вместо перерисовки после каждой иконки.
- Миниатюры загружаются с ограничением размера декодирования до 2× видимого разрешения.
- Прокручиваемые списки переиспользуют карточки (`reuseItems`) и небольшой буфер предварительной отрисовки.
- Каталоги персонажей и избранного повторно используют результаты выборки, не вызывая бэкенд несколько раз за один цикл QML.
- Поиск в избранном и галерее внешности обновляется после короткой паузы ввода (160 мс).
- Windows CI проверяет изменение размеров окна и масштабирование интерфейса.

## Если автообновление зависло на Beta 12

В Beta 12–15 на экране был зафиксирован текст `v2.28.0-qt-beta.12`, даже если EXE фактически обновился. Если версия не изменилась и по содержимому приложения, проверьте `dbd_update_error.log` в папке с EXE. В Beta 16 установщик дополнительно ведёт `dbd_update_progress.log` и показывает последнюю ошибку внутри приложения.

Для однократного ручного обновления остановите программу, сделайте резервную копию пользовательских JSON-файлов и целиком распакуйте новый portable ZIP в **отдельную папку**; запускайте EXE рядом с `_internal`. Автоматический механизм старой Beta 12 невозможно исправить без замены её файлов.

## Beta 17 — прогресс и контроль автообновления

В настройках после нажатия «Скачать и установить» показывается прогресс загрузки, затем проверка SHA-256, распаковка и подготовка установки. До выхода программы новый EXE не перезаписывается. Реальный сценарий Beta 16 → Beta 17 проверяется в Windows CI **до** публикации prerelease на отдельно распакованных portable-сборках, без изменения пользовательских файлов. Публикация релиза активируется только из preview-ветки.

## Поиск процесса Dead by Daylight

Автоэкипировка больше не сравнивает заголовок окна с «Dead by Daylight». Для Steam/Epic ищется процесс `DeadByDaylight-Win64-Shipping.exe`, для WinGDK — `DeadByDaylight-WinGDK-Shipping.exe`. Если игра запущена, но автоэкипировка пишет, что процесс не активен, проверьте реальное имя EXE в диспетчере задач и передайте его разработчику. Проверка фокуса по процессу остаётся включённой: клик в другое приложение блокируется.

## Beta 18: ручное переключение перед автоэкипировкой

Название процесса и заголовок окна DBD больше не проверяются. Нажмите «Экипировать», переключитесь в игру во время отсчёта (минимум 3 секунды), и приложение зафиксирует текущее окно для ввода. Если рандомизатор остался на переднем плане или затем активным стало другое окно, автоматизация прекращается. Проверьте координаты в «Сухом прогоне». Стоп — F9 либо выбранная клавиша.

## Beta 21 — проверка русской базы внешности

- База наборов одежды и обликов пересобрана по wiki.gg для `10.2.2_live` и русской вики. Подтверждённые русские названия показаны в интерфейсе; если русского перевода нет, оригинальное имя сохраняется.
- Защищены неизменные ID старых наборов: изменения исходных номеров wiki.gg не должны переназначать сохранённые отметки владения.
- В `tools/catalog_audit.md` и `tools/catalog_audit.json` перечислены скины без RU-названий, а также результаты проверки справочников перков и аддонов.
- Проверка внутренних таблиц **не означает**, что любое имя подтверждено внутри актуального игрового клиента. Оставшиеся имена требуют проверки по игре или достоверной локализации.

## Beta 22 — прозрачность перевода внешности

- В галерее отображаются русские и английские имена комплектов, источник русского сопоставления и количество записей с RU-названиями.
- Фильтры «Все названия», «С RU», «Без RU» помогают найти неподтверждённые переводы; фильтрация не меняет список доступных скинов и настройки.
- При переключении между выжившими и убийцами выбирается первый персонаж соответствующей стороны, чтобы галерея не показывала старую подборку.
- Аудит базы защищает даже от переназначения ID другому комплекту того же персонажа.
- Неподтверждённые имена из локализации игры не придумываются и не заменяются автоматически.

## Release Candidate 1 — финальная проверка

- Версия кандидата: `v3.0.0-qt-rc.1`; сборка остаётся совместимой с прежними ZIP/EXE-именами (`DBDRandomizerQtBeta.zip`, `DBDRandomizerQtBeta.exe`) во избежание поломки установщика.
- Обновлятор RC понимает будущие теги Qt RC и Stable. **Важное ограничение:** уже выпущенная Beta 22 распознаёт только `-qt-beta.N`, поэтому автоматически не обнаружит тег RC 1. Для тестирования RC 1 используется отдельный ZIP или сначала нужен совместимый промежуточный Beta-релиз; не устанавливайте кандидат поверх основной папки до подтверждения сохранности настроек.
- Перед Stable обязательны тест экипировки в реальной DBD и проверка обновления на обычном ПК. Гайд: `docs/RC1_TEST_PLAN_RU.md`.
