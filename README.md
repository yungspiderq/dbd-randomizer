# DBD Ultimate Search Randomizer

Случайный генератор билдов для Dead by Daylight (выжившие и маньяки) с авто-экипировкой
через поиск в инвентаре. Русская локализация клиента, Windows.

**Версия 2.4.1** · база данных: патч **10.1.2a** (44 убийцы, 54 выживших) · 65 автотестов

---

## Возможности

- 🎲 Рандомизация билдов: персонаж, сила/предмет, 2 аддона, 4 перка
- 🌍 **Билды сообщества**: публикация своих билдов и экипировка чужих (вкладка «БИЛДЫ»)
- 🛠 **Конструктор билдов**: название, описание, персонаж, аддоны и 4 навыка вручную
- 🕶 **Публикация без токена**: анонимное облако Firebase вместо GitHub (по желанию)
- 🎰 Режим навыков «Случайные: любые 4 из всех навыков»
- 🎭 Отметка доступных персонажей — невыбранные не выпадают
- 🎯 Настройка координат кликов под ваше разрешение, захват кликом
- ⚡ Авто-экипировка: слот → имя в поиск → выбор результата
- ⏹ Мгновенная остановка: `F9`, кнопка в окне или мышь в левый верхний угол
- 🧪 «Сухой прогон» — весь план кликов в журнале, без единого реального действия
- 🔎 Опциональная OCR-проверка: программа читает имя найденного предмета и не кликает, если оно не совпало
- 🩺 Валидатор базы: дубли, коллизии имён, имена-префиксы, подозрительные переводы
- 🔄 Автообновление из релизов GitHub — с показом SHA-256 и резервной копией `.bak`
- 🖼️ **Настоящие иконки** в карточке билда: 320 перков, 768 аддонов, 54 портрета выживших,
  37 портретов маньяков (кроп из спрайт-листа), 41 иконка сил и 37 иконок предметов
- 🌑 Полностью тёмная тема: список билдов, поля ввода, прогресс-бар и скроллбары больше не белые

## Установка

**Способ 0 — БЕЗ Python (Windows):** скачайте `DBDRandomizer.exe` из
[Releases](https://github.com/yungspiderq/dbd-randomizer/releases) (ассет к релизу,
собирается GitHub Actions) и просто запустите. Python, pip и bat-ники не нужны.
Конфиг, база и кэш иконок создаются **рядом с exe**; обновления приходят новыми
exe-файлами (автозамена .py в EXE-сборке отключена намеренно).

**Способ 1 — самый простой (Windows):** скачайте ZIP репозитория (Code → Download ZIP),
распакуйте и запустите `install.bat` — он установит зависимости и откроет программу.
Дальше запускайте `run.bat`.

**Способ 2 — через pip:**
```bash
pip install -r requirements.txt
python dbd_randomizer.py
```
или установка как пакета (появятся команды `dbd-randomizer` и `dbd-rand`):
```bash
pip install .
dbd-randomizer
```

**Способ 3 — одной командой с GitHub:**
```bash
pip install git+https://github.com/yungspiderq/dbd-randomizer.git
dbd-randomizer
```

OCR-проверка (необязательно): `pip install -r requirements-optional.txt` +
[установщик Tesseract](https://github.com/UB-Mannheim/tesseract/wiki) с русским языком.

Windows + Python 3.8+. Окно игры должно быть на том же мониторе и в том же разрешении,
в котором снимались координаты. Программа сама включает DPI-awareness, поэтому масштаб
Windows 125/150 % больше не «сдвигает» клики.

## Первый запуск

1. Вкладка **ПЕРСОНАЖИ** — отметьте открытых персонажей (есть фильтр и кнопки
   «Все / Никого / Инвертировать») → Сохранить.
2. Вкладка **КЛИКИ И ТАЙМИНГИ** — для каждого поля жмите «🎯 Клик», наводите мышь
   на нужную точку и кликайте в появившемся окне. Координаты видны в реальном времени,
   `Esc` — отмена.
3. Включите **«Сухой прогон»** и нажмите «⚡ ЭКИПИРОВАТЬ В ИГРЕ» — журнал покажет весь
   план действий без единого клика. Проверьте имена.
4. Снимите галку, откройте в игре меню снаряжения и запускайте по-настоящему.

### Обязательные координаты

| Поле | Когда нужно |
|---|---|
| `search`, `first_result` | всегда |
| `addon1_slot`, `addon2_slot` | если подобраны аддоны |
| `slot1`…`slot4` | под навыки |
| `item_slot` | только для выживших |
| `clear` | только если включена галка «кликать × очистки» |
| `char_search` | только если включено «самому выбрать персонажа» |
| `ocr_region` | только при включённой OCR-проверке (кнопка «🔎 Область» — два клика по углам) |

### Тайминги (настраиваются)

| Параметр | По умолчанию | Зачем |
|---|---|---|
| `search_settle` | 0.35 с | пауза после ввода имени, пока игра фильтрует выдачу |
| `after_slot_click` | 0.45 с | пауза после клика по слоту |
| `hold` | 0.06 с | удержание кнопки мыши |
| `between_steps` | 0.25 с | пауза между шагами |
| `retries` | 2 | сколько раз повторить неудачный поиск |
| `countdown` | 5 с | обратный отсчёт перед стартом |
| `move_steps` | 6 | шагов перемещения курсора (1 = мгновенно) |
| `result_step` | 84 px | шаг сетки выдачи для `result_index > 1` |

Если игра «не успевает» — увеличьте `search_settle` до 0.6.

## 🌍 Билды сообщества

- Вкладка **«БИЛДЫ»** — все опубликованные билды: фильтр по стороне, поиск, карточка деталей
- **Публикация**: сгенерируйте билд → «🌍 ОПУБЛИКОВАТЬ БИЛД» → он появится у всех пользователей
- **Экипировка чужого билда**: выберите строку → «⚡ Экипировать выбранный»
- Двойной клик по строке — копировать карточку в буфер обмена
- Без интернета список берётся из локального кэша `community_builds_cache.json`

### Как включить публикацию (один раз)

1. Создайте токен GitHub: [Settings → Developer settings → Fine-grained tokens](https://github.com/settings/tokens?type=beta)
   - Repository access: **Only select repositories** → `dbd-randomizer`
   - Permissions: **Contents → Read and write**
2. Вкладка «БИЛДЫ» → блок «🔑 НАСТРОЙКА ПУБЛИКАЦИИ»: ник и токен → «💾 Сохранить настройки».

Для **чтения** списка билдов токен не нужен. Публикация идёт через Contents API с передачей
`sha` файла, поэтому чужие публикации не затираются; при гонке (HTTP 409) делается один повтор.
Формат записей совместим с v1.1.x — старые билды читаются и экипируются как раньше.

> ⚠️ **Не храните токен в файлах репозитория.** `dbd_randomizer_config.json` (где лежат ник
> и токен) добавлен в `.gitignore`. В v1.1.1 первая строка `.gitignore` была склеена
> (`__pycache__/dbd_randomizer_config.txt`), из-за чего конфиг **не** игнорировался и мог
> уехать в коммит вместе с токеном.

## 🔄 Автообновление

Программа проверяет релизы GitHub при запуске и каждые 30 минут. Отключить:
вкладка **КЛИКИ И ТАЙМИНГИ** → блок «АВТООБНОВЛЕНИЕ».

В отличие от v1.1.1, обновление больше не является «дырой в любой ПК»:

| | v1.1.1 | v2.0.0 |
|---|---|---|
| Откуда качается | ветка `main` (любой push сразу у всех) | **тег релиза** |
| Что качается | только `dbd_randomizer.py` | все модули сразу, во временные файлы |
| Проверка содержимого | размер > 1000 байт | размер + маркер + **компиляция синтаксиса** |
| Что видит пользователь | номер версии и notes | версия, notes, размер и **SHA-256** каждого файла |
| Откат | нет | старые файлы сохраняются как `.bak` |
| Риск «полуобновления» | есть | нет: замена только после проверки всего бандла |
| Конфиг и токен | могли быть перезаписаны | не затрагиваются никогда |

Кнопка «Позже» запоминает версию в `skip_tag` и больше её не предлагает.
Флаг «Брать файлы из main, если релизов нет» по умолчанию **выключен**.

## 🖼️ Иконки и портреты

В карточке билда показываются настоящие иконки всего содержимого билда:

| Что | Покрытие | Источник |
|---|---|---|
| Навыки (перки) | 320/320 | `IconPerks_*` wiki.gg |
| Аддоны | 768/788 (15 удалены из игры) | `IconAddon_*` / `T_UI_iconAddon_*` |
| Портреты выживших | 54/54 | `Survivor*.png` |
| Портреты маньяков | 37/44 (K38+ ещё не отрисованы на вики) | кроп кадра из `KillerPortraitsSprite.png` |
| Силы маньяков | 41/44 (нет у K39–K41) | `IconPowers_*` |
| Предметы выживших | 37/39 (нет у двух старых карт) | `IconItems_*` |

Портрет персонажа рисуется слева от имени, иконка силы/предмета — слева от её
названия; у аддонов и навыков иконки в своих строках. Всё докачивается фоном и
кэшируется в `icons_cache/` (спрайт маньяков качается один раз, ~3 МБ, и режется
на кадры локально).

Иконки **не лежат в репозитории**: это ассеты Behaviour Interactive, и перераспределять
их в публичном репо — лишний юридический риск (и +10 МБ бинарников в истории git).
Вместо этого:

- `dbd_icons.py` хранит только карты «русское имя → имя файла на вики» — `PERK_ICONS`
  (сгенерирована `tools/resolve_icons.py`) и `ADDON_ICONS` (сгенерирована
  `tools/resolve_addon_icons.py`) по API deadbydaylight.wiki.gg;
- при показе билда недостающие PNG докачиваются фоном и кэшируются в `icons_cache/`
  (папка в `.gitignore`);
- кнопка **«⬇ Все иконки»** предзагружает весь набор разом — удобно перед игрой без
  интернета;
- пока иконка не скачалась, на её месте заглушка; текст навыка виден в любом случае;
- для отрисовки нужен **Pillow** (`pip install Pillow`, уже в `requirements.txt`).

Карта собрана автоматически: имена файлов на вики образуют три разных семейства
(`IconPerks_*`, `IconPerks <id>.png`, `T_UI_iconsPerks_*`, плюс `IconsPerks_*`), поэтому
сопоставление шло по нормализованному внутреннему ID, нечётному сравнению и, для трёх
особых случаев, по изображениям на странице навыка. Покрытие проверяется тестом
`test_every_perk_has_icon`: если в базе появится навык без иконки, тесты упадут.

Для аддонов цепочка такая: `Module:Datatable/Loadout` и `Module:Datatable/Icons` с вики
дают «англ. имя → файл иконки», а `tools/addon_names_ru_en.py` — сверенную вручную таблицу
«русское имя (как в `dbd_data.py`) → англ. имя». Имя файла дополнительно проверяется по
списку реально залитых на вики файлов (`IconAddon_x.png` и `IconAddon x.png` — разные
файлы). Покрытие — 768 из 788 аддонов базы (97 %); остальные 15 полностью удалены из игры
и не существуют даже в таблице вики — они перечислены в тесте
`test_every_addon_has_icon` как разрешённые исключения.

## Настройка генерации

| Режим навыков | Что выпадает |
|---|---|
| Смешанные **(по умолчанию)** | 3 своих уникальных перка персонажа + 1 общий |
| Уникальные | 3 своих перка персонажа + 1 уникальный любого другого персонажа |
| Случайные | любые 4 из навыков стороны: свои, общие и уникальные **только отмеченных** персонажей |
| Общие навыки | 4 из списка общих — есть у всех, автоэкипировка не промахнётся |

До v2.2.0 по умолчанию стоял режим «Общие», а «Смешанные» перемешивали общий пул
(3 своих + 13 общих) — поэтому почти всегда выпадали только общие навыки. Теперь
режимы дают ровно то, что обещают, а дефолт — «Смешанные»; старые конфиги с
`perk_mode: general` один раз переводятся на `mixed` автоматически.

Галка **«Только открытое у меня»** включает белые списки из `dbd_database.json`
(секция `owned`: `killer_perks`, `killer_addons`, `survivor_perks`, `survivor_items`,
`survivor_addons`). Пустой список = «открыто всё». Если набрать 4 перка не удалось,
лишние слоты остаются пустыми и **не кликаются**.

## Правка базы данных

При первом запуске создаётся `dbd_database.json` — редактируемая копия встроенной базы
(`dbd_data.py`). Правки подхватываются при следующем запуске.

```json
"Охотник": {
  "power": "Медвежий капкан",
  "addons": ["Кровавая пружина", "Точильный камень", "..."],
  "perks": ["Невероятная стойкость", "Зверская сила", "Порча: тотем охоты"]
}
```

Правила: имя (ключ), `power`, `addons`, `perks` — **ровно как в игре**, символ в символ
(регистр поиск не учитывает, а вот `ё`/`е`, пробелы и «ёлочки» — важны); 3 уникальных
навыка на персонажа. После правки нажмите **«🩺 Проверить базу данных»** — отчёт покажет
ошибки, дубли, коллизии имён и имена-префиксы, а также сохранится в `dbd_data_report.txt`.

### ⚠ Что стоит сверить с игрой

| Запись | Почему |
|---|---|
| **Судья** / «Воля богов» / 3 навыка | новый убийца 10.1.0 (25.08.2026). Фан-вики пишет «Правосудие», новости — «Судья». Аддоны пока не заполнены — шаг пропустится |
| **Аврора** / 3 навыка | новый выживший 10.1.0 |
| **Сейбл Уорд** | в игре вероятно «Сэйбл Уорд» |
| **Егерь** | возможен официальный вариант «Псарь» |
| **Ксеноморф → «Скрытная погоня»** | EN *Hidden Pursuit*; у вас же это имя стоит перком Гоуст Фейса |
| **Неведомое → «Свободное»** | EN *Free Play* |

## Разработка

```bash
python dbd_randomizer.py --selftest   # проверка базы и генератора (без GUI, работает и не в Windows)
python smoke_test.py                  # 45 тестов: генерация, валидация, автоматизация, сеть
```

`smoke_test.py` подменяет tkinter и бэкенд ввода заглушками, поэтому тестирует логику
на любой ОС без игры. Сетевые тесты не выходят в интернет — HTTP-слой подменяется.

Модули:

| Файл | Назначение |
|---|---|
| `dbd_randomizer.py` | UI + автоматизация кликов |
| `dbd_data.py` | встроенная база (персонажи, аддоны, предметы) |
| `dbd_github.py` | билды сообщества, автообновление, HTTP — без tkinter |
| `dbd_icons.py` | **сгенерировано**: карта «RU имя → файл иконки» |
| `dbd_icons_store.py` | загрузка и кэш иконок — без tkinter |
| `tools/resolve_icons.py` | генератор `dbd_icons.py` (нужен доступ к wiki.gg API) |
| `tools/perk_icon_ids.py` | внутренние ID иконок, разобранные из RU-вики |

Пересобрать карту иконок: `python tools/resolve_icons.py`.

## Известные ограничения

- **Редкости аддонов не учитываются** — игра не примет два аддона одинаково высокой
  редкости, такой билд придётся поправить руками.
- **Событийные предметы** («Маскарадный фонарик», «Банкетная аптечка»…) есть не у всех —
  используйте белые списки `owned`.
- **Поиск подстрочный**: при совпадении имён берётся иконка №`result_index`
  (валидатор показывает все конфликтные пары). Надёжнее всего — включить OCR.
- `keyboard` (клавиша СТОП) иногда требует запуска от администратора, если DBD запущен так же.
- Сменили разрешение или раскладку интерфейса — переснимите координаты.
- **Иконки требуют интернет** при первом показе навыка (дальше — из кэша). Без Pillow
  карточка остаётся текстовой.
- Трёх иконок на вики не было под ожидаемыми именами (`Барбекю и чили`, `Ненависть`,
  `Жестокая изоляция`) — они найдены через страницы навыков и внесены в
  `MANUAL_FILES`; EN-имена у них отличаются от внутренних ID
  (`Barbecue & Chilli`, `Rancor`, `Cruel Limits`).

## 🛠 Конструктор билдов

Вкладка **«КОНСТРУКТОР»** — сборка билда вручную, без генератора:

- «паспорт»: **название** (до 60 символов) и **описание** (до 300) — видны в карточке,
  в списке билдов сообщества (колонка «Название») и в тексте для копирования;
- сторона → персонаж → (у выживших категория и предмет) → 2 аддона → 4 навыка
  (выпадающие списки показывают только то, что бывает у этого персонажа);
- кнопки: «🎲 Случайные перки», «👁 В карточку», «📋 Копировать»,
  «⚡ Экипировать», «🌍 Опубликовать».

## 🕶 Публикация без токена (Firebase)

GitHub не умеет принимать записи без авторизации, а kvdb.io требует привязку карты,
поэтому анонимный канал сделан на **Firebase Realtime Database** (бесплатный тариф,
без карты — нужен только Google-аккаунт владельца):

- во вкладке «БИЛДЫ» → «КАК ПУБЛИКОВАТЬ» выберите **«Облако Firebase (БЕЗ токена)»**;
- запись — append-only (`POST` с push-ключом): чужие билды невозможно перезаписать;
  правила БД дают всем чтение и создание, но не изменение/удаление;
- список билдов читается из ОБЕИХ каналов сразу (GitHub + Firebase), дубли гасятся по id;
- URL базы хранится в настройках (`firebase_url`); в релиз прошит дефолт владельца:
  `https://dbdbuilds-41c0c-default-rtdb.firebaseio.com` — работает из коробки.

### Как владелец создаёт базу (3 минуты, без карты)

1. https://console.firebase.google.com → **Add project** (имя любое, аналитику можно выключить).
2. Слева **Build → Realtime Database → Create Database** → регион любой → **Start in locked mode**.
3. Вкладка **Rules** → вставить и **Publish**:
   ```json
   {
     "rules": {
       "community_builds": {
         ".read": true,
         "$push": { ".write": "!data.exists()" }
       }
     }
   }
   ```

## Что исправлено в v2.0.0

Подробный разбор — в [`AUDIT.md`](AUDIT.md). Коротко о критичном:

- **Клик по устаревшей выдаче.** `time.sleep(0.01)` после вставки имени не давал игре
  отфильтровать список — нажималась иконка прошлого результата. Теперь пауза настраивается,
  есть повторы и OCR-контроль.
- **Tkinter из рабочего потока.** `status.config(...)` и `messagebox` вызывались из потока
  автоматизации — гонка, случайные краши. Теперь очередь + `root.after`.
- **Окно захвата координат съедал сборщик мусора** (`grabber` был локальной переменной).
- **Невозможно остановить** угон мыши — добавлены `F9`, кнопка СТОП, прерываемые паузы.
- **Два противоречащих списка перков** (`ALL_KILLER_PERKS` и мёртвый `KILLER_PERKS`)
  с разными переводами одних и тех же навыков — оставлен один источник истины.
- **Маньяку выдавались перки всех убийц**, включая неоткрытые.
- **`random.sample(pool, 4)` падал** при пуле меньше четырёх.
- **Конфиг в рабочей директории** (`"dbd_randomizer_config.txt"`) — терялся при запуске
  ярлыком; разбор `split("=", 1)` без `strip` молча терял значения. Теперь JSON рядом со
  скриптом, атомарная запись, автоматическая миграция со старого `.txt`.
- **Нет DPI-awareness** — клики «уезжали» при масштабе Windows ≠ 100 %.
- **`import pydirectinput` на верхнем уровне** ронял скрипт вне Windows.
